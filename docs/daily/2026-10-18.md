# Part 7 - Show uncertainty, not just one forecast

Completed 18 October 2026. Today we added a range around each forecast. We used January-June 2017 errors to decide how wide the range should be, then kept it unchanged while checking July-December. We respected the two-hour reporting delay and kept the final holdout sealed.

The tree's nominal 90% ranges included the actual count in 90.3% of 4,397 observed hours. Their average width was 843.1 vehicles/hour, compared with 1,180.8 for the baseline, which covered 88.3%. A narrower useful range helps communicate uncertainty more clearly than a single number.

The important limitation: coverage was only 76.6% at 22:00 and 86.2% in December. A good overall percentage does not mean every forecast is reliable. We kept those failures visible instead of changing the range after seeing the answers. This is a development check on previously inspected data, not a guarantee of future coverage.

All 49 tests passed with no skips. Independent calculations matched the radii and overall/monthly/hourly interval metrics; a repeated full run reproduced the same report and prediction hashes. Both point forecasts still match Part 5. See [the report](../INTERVAL_RESULTS.md) for the methods and limitations.
