# Part 1 — Can we trust the starting data?

## What we did today

We chose a practical question: how many vehicles will pass a road sensor in the next hour? We downloaded the original public dataset, recorded its source and fingerprint, and wrote a program that checks its structure. We also wrote small tests using made-up example rows, so we can check the program's behavior without depending on an internet connection.

## What we learned

The file has 48,204 rows, but they represent only 40,575 distinct timestamps. Some hours have several rows. There are also 11,976 absent hourly slots between the first and last timestamps, using the source-clock assumption. There are no blank cells. So “no missing values” does not mean we have every hour.

Think of a classroom attendance book: every filled-in page can be complete, while whole days are missing from the book. Also, writing the same day's attendance twice does not double the number of students.

There are 17 exact duplicate rows and 10 rows with nonpositive Kelvin temperature. We flagged them rather than silently changing them. Repeated timestamps do not have conflicting traffic counts in this file.

## Why this matters

If we count every row as a separate hour, repeated hours get extra influence. If we use the previous row as “one hour ago,” a missing day could make that feature incorrect. If we feed the model the actual weather during the hour we are trying to predict, it may be using information that would not yet exist.

Today we built the foundation. We have not trained a model, measured forecast accuracy, or demonstrated savings.
